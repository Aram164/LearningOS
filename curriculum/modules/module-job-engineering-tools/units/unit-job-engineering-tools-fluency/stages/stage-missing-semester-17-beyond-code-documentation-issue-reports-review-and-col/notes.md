# Stage Working Notes

## Mental Models

### Tool model

engineering work transfers context through READMEs, comments, commit/PR messages, issues, design notes, review, teaching, and synchronous decisions; each artifact has a different audience and persistence.

### Working practice

explain why and trade-offs, provide minimal reproductions and environment facts, search before reporting, respect maintainer time, separate blocking correctness from preference, and record decisions that future readers cannot reconstruct from code.

### Job relevance

a correct Stratum change must be understandable, reviewable, and supportable by teammates.

### Failure mode

comments that restate code, issue reports without reproduction, review as style policing, or decisions trapped in chat.

## Read-only Anchor

Read-only in Stratum: assess one README path, one explanatory comment, one commit message, and one test name for how well each preserves intent. Draft improvements outside the checkout; do not edit or submit them.
