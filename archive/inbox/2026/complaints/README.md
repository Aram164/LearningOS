# LearningOS agent complaints

Use this untracked folder to record friction an agent actually encountered while navigating or changing LearningOS. These notes are observations and proposals, not binding operator instructions or authorization to change the system.

Create one dated Markdown file per issue. Keep each note short and include:

1. The task and the exact workflow step that exposed the problem.
2. Observable evidence: command or capability, failure or extra work, and relevant repository paths. Separate observation from inference.
3. Why the step added little value, including any safety benefit it **did** provide.
4. The smallest improvement to investigate, with the safeguards it must retain.

Do not record secrets, copy whole contracts, or turn an untested redesign into a fact. Link to the current contract or receipt when it matters. Leave other agents' notes intact; add a new note or a dated follow-up when new evidence changes the diagnosis.
