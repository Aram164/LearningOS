# Finding: `npm run stage-plugin` — a backup-precondition generator WORKFLOWS §31 names does not exist

## What the document claims

`system/WORKFLOWS.md:988` (§31 "Back up and restore", the workflow that
`system/procedures/back-up-and-restore.md` is the executable transcript of):

> the Obsidian UI checkout in full (…; the plugin's `plugin/build-info.json`
> must exist, generated by `npm run stage-plugin` or `npm run build` in
> obsidian-ui);

## What the repository does

At the pinned UI checkout `f7dbc1f7607157d5c1c2edb84a14e6a26ab89f94`,
`npm run stage-plugin` fails: there is no such script. The other named
generator, `npm run build`, works and produces the file.

Exact command and output (probe:
`findings/stage-plugin-not-a-script/stage-plugin-probe.sh`, full output in
`logs/stage-plugin-probe-output.log`):

```
$ cd obsidian-ui && npm run stage-plugin
npm error Missing script: "stage-plugin"
exit=1

$ cd obsidian-ui && npm run build
exit=0
plugin/build-info.json exists afterwards: yes
```

`git log --all --oneline -S"stage-plugin"` over the UI repository returns
nothing: no commit in the UI's history ever contained the string, so the
script never existed under that name. `package.json` at the pin declares no
`stage-plugin` script, and no file in the UI repository (outside
`node_modules`) mentions it. The only reference in either repository is
`system/WORKFLOWS.md:988` in Core.

## Why it matters for this workflow

`backup-manifest` refuses to back up a UI checkout whose declared plugin
assets are missing (`declared plugin asset cannot be backed up:
plugin/build-info.json`, observed on the clone drill before the file was
generated). WORKFLOWS §31 is the recovery guidance for exactly that
refusal, and half of its stated remedy is a command that has never
existed. An operator following §31 literally hits `Missing script` and
must fall back to the undocumented half of the sentence. The procedure
transcript itself sidesteps the problem by writing a hand-labeled
`build-info.json` stand-in instead of generating the file.

## Classification

- **Certainly wrong:** the claim that `npm run stage-plugin` generates
  `plugin/build-info.json`. The script does not exist at the pin and never
  existed in the UI repository's history.
- Observation (not raised as a defect): `npm run build` satisfies the
  precondition, and the rebuilt `plugin/main.js`/`styles.css` were
  byte-identical to the committed ones (`git status` clean afterwards),
  so the working half of the sentence fully unblocks the drill.

## Scope note

The claim lives in WORKFLOWS §31 rather than in the three V5 scope files
themselves; it is reported because V5's scope defines the procedure as
"the executable transcript of WORKFLOWS §31" and the drill depends on the
precondition that line governs. No pytest is attached: this is a
documentation claim, evidenced by the command transcript above, per the
campaign's finding definition.

## Suggested smallest fix

Change `system/WORKFLOWS.md:988` to name `npm run build` alone, or add the
`stage-plugin` script the sentence promises. Either way, one of the two
halves of the sentence is currently false.
